# Sustituto de ImageSharp para fotos - 2026-10-24

El usuario pidio evaluar otra biblioteca. El codigo publicado usa `ImageVariantProcessor` con entrada JPEG/PNG/WebP de hasta 8 MB, una sola imagen, dimensiones entre 800x600 y 8000 por lado, variantes sin agrandar, WebP con perdida y calidad configurable, mas SHA-256 del original. La suite actual muestra avisos NU1902/NU1903 para ImageSharp 3.1.12. La cola de fotos sigue apagada.

| Opcion | Evidencia externa verificada | Encaje y riesgo |
|---|---|---|
| [Magick.NET-Q8-AnyCPU 15.0.0](https://www.nuget.org/packages/Magick.NET-Q8-AnyCPU) | Licencia Apache-2.0, paquete de ~84 MB publicado el 10/10/2026; el [proyecto](https://github.com/dlemstra/Magick.NET) declara soporte Windows y Linux. Expone [limites de recursos](https://github.com/dlemstra/Magick.NET/blob/main/src/Magick.NET/ResourceLimits.cs). | Candidato preferido para un prototipo: cubre lectura, redimensionado y WebP sin clave comercial. Configurar limites antes de aceptar archivos no confiables. |
| [SkiaSharp y NativeAssets.Linux](https://www.nuget.org/packages/SkiaSharp.NativeAssets.Linux/4.152.1) | Licencia MIT; el paquete nativo Linux pesa ~63 MB. | Alternativa posible, pero necesita coordinar binarios nativos de Windows/Linux y comprobar decodificacion, orientacion y WebP en ambos entornos. No hay prototipo ni ensayo de seguridad en este proyecto. |
| [ImageSharp 4.1.3](https://www.nuget.org/packages/SixLabors.ImageSharp/4.1.3) | El [aviso](https://github.com/advisories/GHSA-jjfr-hcj7-qf5w) indica parche desde 4.1.2; [Six Labors](https://docs-v3.sixlabors.com/articles/imagesharp/index.html) exige clave de licencia de compilacion para dependencia directa desde 3.2.0. | No es la via elegida por el usuario mientras se evalua otra biblioteca. |

Decision tecnica provisional: prototipar Magick.NET en la rama aislada, con pruebas sinteticas de JPEG/PNG/WebP, corrupcion, bytes que contradicen MIME, dimensiones limite, primera imagen, salida WebP y tamano, cancelacion y ejecucion en Linux. Solo retirar ImageSharp si el prototipo pasa `dotnet test`, `dotnet build`, `dotnet list package --vulnerable` y el ensayo del contenedor. El paquete y el procesamiento de fotos no se cambiaron en esta entrega.

## Resultado de la entrega posterior del 24/10

- `ImageVariantProcessor` usa Magick.NET-Q8-AnyCPU 15.0.0 para JPEG, PNG y WebP; limita bytes leidos, dimensiones, memoria, disco, hilos y fotogramas, comprueba firma/MIME y genera variantes WebP tras aplicar orientación EXIF. La API conserva la huella del original y no agranda imágenes.
- NPOI 2.7.6 traía ImageSharp 2.1.11 de forma transitiva. NPOI 2.8.1 lo elimina, pero su [EULA para binarios](https://github.com/nissl-lab/npoi/blob/master/OSMFEULA.txt) plantea una cuota según ingresos. El usuario eligió reemplazar NPOI. `PropertyImportTableReader` ahora usa ExcelDataReader y OpenMcdf 3.3.0 para leer XLS/XLSX y rechazar fórmulas estructurales; cuatro pruebas con XLS/XLSX sintéticos pasaron. La rama no conserva NPOI ni declara `AcceptNPOIOSMFLicense`.
- Pruebas de imágenes en Windows y Linux: JPEG, PNG, WebP, MIME incorrecto, archivo corrupto, tamaño real mayor al declarado, orientación EXIF, variantes y almacenamiento local. `dotnet list ... package --vulnerable --include-transitive` devolvió lista vacía para Infrastructure. [Magick.NET 15.0.0](https://www.nuget.org/packages/Magick.NET-Q8-AnyCPU/15.0.0) y [OpenMcdf 3.3.0](https://www.nuget.org/packages/OpenMcdf/3.3.0) son las versiones verificadas.
- Esto cierra el bloqueo de dependencia para procesar fotos en la rama. La cola `PropertyMedia`, pruebas con fotos reales y migraciones de producción siguen pendientes; no se activaron fotos ni se desplegó código.
