# Checkpoint — Enlyce — 2026-09-04

## Resumen

Se creó `website/`, una aplicación pública separada del CRM de L&C Propiedad Raíz. Incluye tres prototipos HTML navegables, investigación de Fincaraíz y Metrocuadrado, análisis de brechas del backend y comparación de tecnologías.

## Cambios realizados

- Galería para comparar tres direcciones visuales.
- Concepto 01: editorial premium y propiedades curadas.
- Concepto 02: marketplace urbano con filtros, mapa, favoritos y visitas.
- Concepto 03: experiencia cercana centrada en compradores y propietarios.
- Interacciones simuladas para búsqueda, filtros, favoritos y formularios.
- Dos imágenes originales generadas para el prototipo.
- Investigación funcional de competidores y recomendación de producto.
- Comparación entre Next.js, Astro y Razor Pages.
- Verificador local de referencias, estructura HTML y JavaScript.

## Estado actual

- Los prototipos funcionan como HTML/CSS/JS estático y son responsivos.
- No consumen API ni guardan datos; el inventario y las métricas son simulados.
- Recomendación: combinar la estructura del concepto 02, la estética del 01 y el tono del 03.
- `node website/verify.mjs`: correcto.
- `npm run build` en `frontend/`: correcto.
- `dotnet test Enlyce.slnx --no-restore`: 133 pruebas de dominio y 39 de integración superadas.
- Deuda previa: `Enlyce.Application.Tests` no descubre pruebas y `System.Security.Cryptography.Xml 9.0.0` reporta vulnerabilidades altas conocidas.

## Pendientes / próximos pasos

- Elegir o fusionar dirección visual.
- Recibir logo, colores, fotografías, WhatsApp, dirección y redes de L&C.
- Migrar el diseño elegido a Next.js + TypeScript.
- Crear catálogo público paginado, filtros, galería, coordenadas, slugs y metadatos SEO.
- Conectar formularios, visitas y consentimiento con el pipeline del CRM.
- Definir almacenamiento de imágenes, mapa, hosting y dominio.
- Añadir pruebas de interfaz y accesibilidad en el stack definitivo.

## Decisiones y notas

- `website/` y `frontend/` son aplicaciones distintas: marketplace público y CRM privado.
- Ambas deben compartir `Enlyce.Api`, dominio y PostgreSQL; no duplicar backend en Python o Java.
- Next.js es la opción recomendada por SEO dinámico, renderizado servidor y reutilización de React.
- La ingeniería inversa tomó patrones de UX e información, no identidad, código ni textos ajenos.
- El backend actual carece de consulta pública filtrada, fotos reales, coordenadas, slug y estado de publicación web.
